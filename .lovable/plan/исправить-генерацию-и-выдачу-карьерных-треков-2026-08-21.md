# Исправить генерацию и выдачу карьерных треков

## Подтверждённая причина

Текущая команда создаёт шаблоны треков, но назначает их сотрудникам по другому правилу:

- сотрудник случайно пропускается в 40% случаев;
- из всех подходящих шаблонов выбирается только один;
- если у сотрудника уже есть хотя бы одно назначение, повторный запуск полностью его пропускает.

Поэтому наличие 10+ шаблонов в компании не означает, что сотрудник увидит их. Экран сотрудника показывает только строки из `employee_career_assignments`, относящиеся к выбранному/имперсонируемому пользователю. Кнопка на странице демо-компании работает только с ООО «Демо» и не создаёт треки для компании пользователя `a.shmakov@fenix-bg.ru`.

## Что изменить

1. **Убрать случайное назначение**
  - удалить вероятность 60%;
  - для каждого сотрудника выбрать все активные шаблоны, у которых `from_position_id` совпадает с его текущей должностью;
  - создать недостающие назначения для каждой пары `user_id + template_id`, не удаляя прогресс существующих.
2. **Не пропускать сотрудника из-за одного существующего трека**
  - заменить проверку «у пользователя уже есть назначение» на проверку конкретной пары «пользователь + шаблон»;
  - повторное нажатие кнопки должно дозаполнять новые подходящие треки и оставаться идемпотентным.
3. **Сделать результат кнопки проверяемым**
  - вернуть в выводе число подходящих шаблонов, созданных назначений и сотрудников без подходящих треков;
  - отдельно показать результат для `employee.76@demo.pikrosta.ru` без раскрытия чувствительных данных в общем UI;
  - не сообщать «треки назначены», если для выбранных сотрудников назначения не появились.
4. **Разделить демо и другие компании**
  - кнопку `/superadmin/demo-seed` оставить строго для ООО «Демо»;
  - для `a.shmakov@fenix-bg.ru` проверить фактическую должность, шаблоны его компании и назначения;
  - если в его компании действительно существует только один подходящий шаблон, это корректно отразить, а не приписывать результат демо-генератору. Массово менять данные Fenix демо-кнопка не будет.
5. **Проверка на боевом сервере**
  - нажать генерацию и проверить API/экран под `employee.76@demo.pikrosta.ru`: отображаются все треки от его текущей должности;
  - зайти суперadmin → impersonation `a.shmakov@fenix-bg.ru` и сверить число показанных треков с числом реальных подходящих назначений;
  - повторить генерацию и убедиться, что дублей нет, а прогресс существующих треков сохранён.
6. Создать правило для HRD и HR (если его еще нет):
  1. HRD, HR видит все карьерные треки компании (если иное не предусмотрено политиками конкретной компании)
  2. HRD, HR может создавать карьерные треки для любых должностей (если иное не предусмотрено политиками конкретной компании)
  3. HRD, HR могут редактировать карьерные треки для любых сотрудников (если иное не предусмотрено политиками конкретной компании)

## Технические детали

- Основная правка: `SeedDemoCompany::assignCareerTracks()`.
- Уникальность уже поддерживается на уровне пары `user_id + template_id`; использовать `updateOrInsert`/проверку этой пары.
- Экран `CareerTrack.tsx` менять только если проверка покажет, что API возвращает назначения, но UI их скрывает.
- Добавить регрессионный тест: сотрудник с тремя подходящими шаблонами получает три назначения; повторный запуск по-прежнему оставляет три.
