# План: исправить незавершённые HRD/Employee сценарии и проверить их вручную

## Принцип работы

Задача считается незавершённой, пока каждый пункт ниже не пройден в браузере под реальной HRD/Employee-сессией и не зафиксирован результат: открылась страница, данные видны, действие сохраняется, после перезагрузки состояние не теряется, в консоли и сетевых запросах нет релевантных ошибок.

## Что проверено до плана

- В коде есть маршруты `/users`, `/tests`, `/shop`, `/shop/:id`, `/cart`, `/adaptation-plans`, `/invitations`, `/chats`, `/chats/:conversationId`, `/performance`, `/performance/cycles/:id`, `/pulse-surveys`, `/pulse-surveys/:surveyId`.
- Каталог магазина ведёт на карточку через `Link to={/shop/:id}`, но нужно проверить, не блокируется ли переход layout-ом, правами, ошибкой загрузки товара или пустым `company_id`.
- Карточка товара добавляет запись в `shop_cart_items`, а корзина читает `shop_cart_items` по `user_id`; нужно проверить фактический ответ API/БД и несовпадение идентификаторов пользователя/компании, из-за которого корзина может оставаться пустой.
- В ряде модулей уже есть частичная реализация, но она не считается выполненной без end-to-end проверки: чат, таблица сотрудников, тесты, pulse-опросы, планы адаптации, приглашения, performance review, документы.

## Волна 0. Обязательная диагностика перед правками

1. Запустить Playwright-сценарий под HRD на боевом/актуальном стенде:
   - открыть каждый спорный раздел;
   - собрать console errors, failed network requests, HTTP 4xx/5xx;
   - сохранить скриншоты начального состояния и состояния после действия.
2. Для магазина отдельно снять фактическую цепочку:
   - `/shop` → клик по товару → `/shop/:id`;
   - «В корзину» → запрос создания/обновления cart item;
   - `/cart` → повторное чтение корзины;
   - перезагрузка `/cart` → товар остаётся видимым.
3. Для пустых разделов сверить не предположения, а реальные данные: есть ли строки по текущей компании и текущему пользователю, какой `company_id/user_id` используется клиентом и что возвращает backend.

## Волна 1. Магазин и корзина

- Починить вход в карточку товара: маршрут, доступ, обработку отсутствующего товара, загрузку `company_id`, кликабельную область карточки.
- Починить добавление в корзину: единый `user_id`, `company_id`, upsert/insert/update, инвалидация query cache и читаемость корзины сразу после добавления.
- Добавить явное состояние ошибки на карточке и в корзине, чтобы 403/404/500 не выглядели как «пусто».
- Проверить: товар открывается, добавляется, виден в корзине после перехода и после reload; при нехватке валюты добавление блокируется с понятной подсказкой.

## Волна 2. Чат

- Проверить список диалогов, открытие диалога, отправку сообщения, отображение имени/аватара отправителя, переход по аватару в профиль и запуск лички из профиля/сообщества.
- Исправить недостающие связи профиля отправителя, создание 1:1 диалога и обработку пустых/запрещённых диалогов.
- Проверить HRD ↔ Employee: сообщение отправлено, видно обеим сторонам, после reload остаётся.

## Волна 3. Таблица сотрудников

- Проверить `/users` под HRD: загрузка всех сотрудников компании, фильтры, drill-down параметры из аналитики, карточка сотрудника, отсутствие вечного loader-а.
- Исправить права/запросы/ошибочные фильтры, если таблица пустая при наличии сотрудников.
- Проверить: список содержит сотрудников текущей компании, поиск и фильтры не обнуляют выдачу ошибочно, профиль открывается.

## Волна 4. Оценка и тесты

- Проверить раздел тестов: создание вручную, импорт из файла, сохранение вопросов, назначение аудитории, включение/выключение теста.
- Проверить пользовательский сценарий прохождения теста и появление результата/попытки.
- Исправить сохранение `audience_rules`, привязку к позиции/отделу/сотрудникам и отображение пустых состояний.

## Волна 5. Pulse-опросы

- Проверить создание опроса, CSV-импорт вопросов, назначение по отделам/аудитории, запуск, прохождение сотрудником, аналитику ответов.
- Исправить таргетинг, импорт, страницу `/pulse-surveys/:surveyId`, сводку «вопрос × ответы» и поимённый разрез для неанонимных опросов.
- Проверить: HRD создаёт и назначает, Employee видит назначенный опрос, ответ сохраняется, HRD видит статистику.

## Волна 6. Планы адаптации

- Проверить создание шаблона, добавление шагов, вложение файла к шагу, назначение сотруднику, отображение прогресса.
- Исправить загрузку вложений, связь шагов с планом, создание assignment и список назначений.
- Проверить: план и шаги сохраняются, вложение открывается/скачивается, назначение видно после reload.

## Волна 7. Приглашения

- Проверить ручное приглашение и импорт CSV/XLSX: валидный email, невалидный email, уже приглашённый, уже зарегистрированный, повторная отправка.
- Исправить сообщение «не указана компания», передачу `company_id`, статусы приглашений и resend/cancel.
- Проверить: приглашение создаётся в списке, письмо/ошибка доставки отображается честно, повторная отправка работает.

## Волна 8. Performance Review

- Проверить HRD: создание цикла, открытие цикла, автосоздание review для сотрудников, переход в деталь цикла.
- Проверить Employee/Manager: самооценка, оценка руководителя, финализация, итоговый score.
- Исправить пустые циклы, ошибку открытия detail route, создание участников и статусы.

## Волна 9. Документы

- Проверить «мои документы» у сотрудника и «все сотрудники» у HRD: список, загрузка, открытие, скачивание, удаление по правам.
- Исправить доступ к чужим документам только для разрешённых ролей и непосредственного руководителя, а также безопасную ссылку скачивания.
- Проверить: сотрудник видит только свои документы, HRD видит документы сотрудников компании, скачивание работает.

## Финальная приёмка

- Один Playwright-прогон по всем пунктам выше под HRD.
- Отдельный Playwright-прогон под Employee по сотрудническим сценариям: чат, тест, pulse-опрос, документы, performance, магазин/корзина.
- Проверка логов: build status, console errors, runtime errors, failed network requests.
- Итоговый отчёт только с фактами: что проверено, какие URL, какие действия, где скриншоты/логи, какие ошибки остались. Если хотя бы один пункт красный — задача не закрывается.
