## Шаг 3. Исправление по результату

В зависимости от того, что покажут шаги 1-2, применяется один из вариантов:

- Отсутствует колонка → миграция, добавляющая её (`deleted_at`, `last_read_at`, `is_support`), плюс защита в контроллере: выборка колонок только из фактически существующих.
- Ошибка не по схеме (память, соединения, сериализация дат) → правка соответствующего места контроллера.
- Пользователь без `company_id` → диалоги отсекаются скоупом; поправить ветку фильтра, чтобы отсутствие компании не роняло запрос.

## Шаг 4. Защита от повторов

Чтобы следующий такой случай не требовал доступа к логам:

- Обернуть `ChatController::index` так, чтобы при исключении возвращался JSON с коротким `error_id`, а полный стек уходил в лог с тем же идентификатором.
- Фронт (`src/components/chat`) при ошибке чатов показывает пустой список и ненавязчивое уведомление вместо падения панели — сессия и остальная страница не страдают.
