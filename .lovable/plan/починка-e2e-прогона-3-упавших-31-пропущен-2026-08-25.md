# Починка E2E-прогона (3 упавших, 31 пропущен)

## Что на самом деле сломалось

Все три падения — одна причина: базовый URL стенда пустой.

- В `src/e2e/support/api.ts` базовый URL берётся как `process.env.E2E_BASE_URL ?? "http://localhost:8080"`. Оператор `??` подставляет запасное значение только для `undefined`/`null`, а GitHub Actions передаёт незаданный секрет как **пустую строку**. В итоге `BASE_URL = ""`, `API_URL = "/api"`.
- Отсюда `page.goto("")` → `Cannot navigate to invalid URL` (гостевой тест на desktop и mobile) и падение `GET /api/health` (нет абсолютного URL для fetch).
- Остальные 31 тест не запускались: `test.skip(!credsFor(role))` — секреты `E2E_<ROLE>_EMAIL/PASSWORD` тоже пустые, поэтому весь ролевой смоук молча пропускается. То есть прогон сейчас ничего не проверяет.

## Что делаю

1. **Устойчивое чтение конфигурации** (`src/e2e/support/api.ts`)
   - Пустые строки трактовать как «не задано»: хелпер `envOrNull()` вместо `??`.
   - Значение по умолчанию для `E2E_BASE_URL` — боевой стенд `https://growth-peak.pro`, чтобы плановый ночной прогон работал даже без секрета.
   - Нормализация URL: добавлять схему, если её забыли (`growth-peak.pro` → `https://growth-peak.pro`), обрезать хвостовые слэши.
   - Аналогично для `credsFor()` — пустая строка = кредов нет.

2. **Явная предполётная проверка** (новый `src/e2e/preflight.spec.ts` или `globalSetup`)
   - Один тест, который печатает используемый BASE_URL и падает с понятным текстом, если стенд недоступен, — вместо загадочного `Cannot navigate to invalid URL`.
   - Если ни для одной роли нет кредов — прогон падает с сообщением «не заданы секреты E2E_*_EMAIL/PASSWORD», а не завершается «31 skipped, зелёный».

3. **Workflow `.github/workflows/tests.yml`**
   - `E2E_BASE_URL: ${{ secrets.E2E_BASE_URL || 'https://growth-peak.pro' }}`.
   - Добавить недостающие `E2E_SUPERADMIN_EMAIL/PASSWORD` (роль есть в ROUTE_MAP, но в env не пробрасывается — поэтому SUPERADMIN всегда skipped).
   - Шаг-диагностика перед прогоном: `curl -sS -o /dev/null -w '%{http_code}' $E2E_BASE_URL/api/health` — сразу видно, жив ли стенд, и не тратится 60-секундный таймаут Playwright.

4. **Проверка результата**
   - Локально прогоняю оба сценария: без переменных окружения (должен использоваться дефолтный прод-URL, тесты либо проходят, либо падают с внятным текстом) и с явно пустым `E2E_BASE_URL=""` — падения `Cannot navigate to invalid URL` быть не должно.
   - Дёргаю `https://growth-peak.pro/api/health` напрямую, чтобы подтвердить, что БД отвечает `ok` и `health`-тест зелёный по существу, а не из-за конфигурации.
   - Прогоняю `bunx tsc --noEmit` и unit-тесты фронта.

## Технические детали

- Правки: `src/e2e/support/api.ts`, `.github/workflows/tests.yml`, новый предполётный спек в `src/e2e/`.
- Ролевые спеки (`src/e2e/api/smoke.spec.ts`, `src/e2e/ui/roles.spec.ts`) не переписываются — меняется только источник конфигурации и режим «нет кредов».
- Бэкенд не затрагивается.

## Что нужно от вас

Чтобы 31 пропущенный тест реально начал прогоняться, в репозитории должны быть заданы секреты `E2E_HRD_EMAIL/PASSWORD` и аналоги для HR, MANAGER, EMPLOYEE, ADMIN, SUPERADMIN (подойдут учётки демо-компании). Если их не задавать — после правки прогон будет честно краснеть с сообщением о недостающих секретах вместо ложно-зелёного «skipped».
