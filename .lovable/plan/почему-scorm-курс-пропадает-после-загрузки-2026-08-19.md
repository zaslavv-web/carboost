# Почему SCORM-курс «пропадает» после загрузки

## Что подтверждено в коде

1. Импорт создаёт курс **со статусом «Черновик»** (`ScormController::import`, статус `draft`).
2. Каталог `/university/courses` (`CourseController::index`) показывает черновики только «авторам».
  Список ролей автора там: `hrd`, `company_admin`, `superadmin` — **роли `hr` нет**.
   При этом загружать и импортировать SCORM роль `hr` **может** (`ScormController::canAuthor` содержит `hr`).
   Итог: HR успешно импортирует пакет, но в каталоге видит только опубликованные курсы, и свой черновик не находит.
3. Каталог всегда фильтруется по `company_id` пользователя: у пользователя без компании (например, superadmin) список пустой.
4. После импорта диалог не сбрасывает кэш списка `["uni-courses"]`, поэтому при возврате на `/university` какое-то время показывается старый список без нового курса.
5. В интерфейсе `/university` нет фильтра по статусу — понять, что курс существует, но в черновике, нельзя.

## Что сделаем

1. **Согласовать права.** В `CourseController::canAuthor` добавить роль `hr`, чтобы список ролей совпадал с тем, кто может импортировать SCORM. Тогда черновики видны тем, кто их создал.
2. **Сделать черновики заметными.** На странице «Корпоративный университет» добавить фильтр статуса (Все / Опубликованные / Черновики) для ролей-авторов, с бейджем «Черновик» (бейдж уже есть) и счётчиком черновиков.
3. **Обновлять список сразу.** В `ScormUploadDialog` после успешного импорта инвалидировать `["uni-courses"]`, чтобы курс появлялся мгновенно.
4. **Понятный итог загрузки.** В тосте после импорта явно писать, что курс создан как черновик и появится сотрудникам после публикации, плюс кнопка перехода к редактированию.
5. **Проверка на бою.** Под боевой учёткой загрузить тестовый SCORM-пакет, убедиться, что курс виден в каталоге с бейджем «Черновик», открывается в редакторе и после публикации доступен сотрудникам.
6. добавить назначение загруженного курса - кто имеет доступ к курсу, кто может его редактировать
7. Добавить аналитический блок по университету в блок аналитика - кто какие курсы прошел, какие сложности в освоении курсов возникают чаще всего - по итогам курсов обычно происходит тестирование - нужно определять на какие вопросы обучающиеся отвечают сложнее всего, количество людей, которые прошли курс против количества людей, которые курс должны были пройти (с возможностью быстрого перехода к сотрудникам, которые по какой-то причине курс не прошли), прогресс прохождения курса общий с быстрым переходом по группам сотрудников находящихся на разных этапах прохождения курса
    


## Технические детали

- `backend-laravel/app/Http/Controllers/Api/CourseController.php` — `canAuthor()`: `['hr','hrd','company_admin','superadmin']`; тот же список применить в `store/update/destroy`, чтобы HR мог редактировать импортированный курс.
- `src/pages/University.tsx` — состояние фильтра статуса, применяется к `catalog.courses`; фильтр рендерится только если пользователь — автор.
- `src/components/university/ScormUploadDialog.tsx` — `useQueryClient().invalidateQueries({ queryKey: ["uni-courses"] })` в `onSuccess` + уточнённый текст тоста.
- Тесты: в `backend-laravel/tests/Feature/ScormControllerTest.php` добавить кейс «HR после импорта видит курс в `/api/university/courses`».
- Изменение бэкенда требует выката: `git pull origin main` и очистка кешей Laravel.
