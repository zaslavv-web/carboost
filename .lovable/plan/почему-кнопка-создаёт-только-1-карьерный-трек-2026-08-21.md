# Почему кнопка создаёт только 1 карьерный трек

## Что происходит сейчас

Кнопка «Назначить карьерные треки» запускает `demo:seed --only-career`. Этот прогон создаёт шаблоны треков только для 14 заранее заданных пар должностей (например «Backend Developer → Fullstack Developer»), и **пропускает пару, если хотя бы одной из должностей нет в базе демо-компании ровно с таким названием**.

То есть число созданных треков полностью зависит от того, какие должности реально лежат в демо-компании на проде. Если названия там другие (по-русски, с другим регистром/пробелами, либо часть должностей не создалась при первом сидинге), почти все пары отбрасываются — остаётся один трек.

Диагноз пока не подтверждён запросом к боевой БД, поэтому первым шагом плана идёт проверка фактических данных, а не правка вслепую.

## Шаг 1. Диагностика (без изменения данных)

Добавить в ответ эндпоинта демо-статуса и в вывод команды:
- список должностей демо-компании (id + название),
- сколько пар из справочника треков сматчилось и какие именно пары отброшены и почему,
- итоговые счётчики `career_templates` / `career_assignments`.

Показать это на странице `/superadmin/demo-seed` — сейчас результат прогона не виден, поэтому непонятно, что именно отвалилось.

## Шаг 2. Сделать создание треков устойчивым

1. **Гибкий матчинг должностей**: сопоставлять названия без учёта регистра, лишних пробелов и русско/английских синонимов (карта соответствий «Разработчик» ↔ «Backend Developer» и т.п.).
2. **Дозаполнение должностей**: если должности из пары нет — создавать её в нужном отделе (с профилем компетенций, как в основном сидере), а не пропускать пару.
3. **Фолбэк по фактическим данным**: если после этого треков всё ещё мало, генерировать пары автоматически из реальных должностей компании (внутри одного отдела: junior → senior роль), чтобы шаблонов было не меньше 10.
4. **Идемпотентность**: не плодить дубли — трек с той же парой `from/to` в компании создаётся один раз.

## Шаг 3. Назначения

После починки шаблонов повторно прогнать назначение: сотрудник получает трек «от своей должности», иначе любой активный. Заодно убрать дублирующийся вызов выбора шаблона в `assignCareerTracks` (лишняя строка `array_rand`).

## Шаг 4. Проверка на бою

- Деплой бэкенда, нажать кнопку на `/superadmin/demo-seed`.
- Убедиться по счётчикам: шаблонов ≥ 10, назначений ≈ 60% сотрудников.
- Playwright-проверка раздела «Карьера» под демо-сотрудником и под HRD.

## Технические детали

- Файлы: `backend-laravel/app/Console/Commands/SeedDemoCompany.php` (`createCareerTracks`, `assignCareerTracks`, `runOnlyCareer`), `app/Http/Controllers/Api/Admin/DemoSeedController.php` (status + careerTracks: возвращать `Artisan::output()`), `src/pages/SeedDemoCompany.tsx` (показ вывода и диагностики).
- Изменения затрагивают только демо-компанию (фильтр по `company_id`), боевые компании не трогаются.
