# Устранение оставшихся 500 на экране сотрудника Today

## Что подтверждено

- Экран уже переведён на лёгкие endpoints для задач и уведомлений, но компетенции и карьерные цели всё ещё запрашиваются через generic `/api/db/*`.
- Именно эти два оставшихся generic-запроса сейчас возвращают 500.
- В таблице `career_goals` нет поля `is_completed`: доступны `status` и `progress`. Текущий frontend запрашивает несуществующее поле и рассчитывает прогресс по неверной структуре.

## Изменения

1. **Один лёгкий endpoint для всего Today**
   - Расширить owner-only endpoint сотрудника так, чтобы одним запросом интерфейса получать:
     - компактный список задач;
     - непрочитанные уведомления и их количество;
     - значения компетенций;
     - карьерные цели с `status` и `progress`.
   - Все выборки выполнять через ограниченные `DB::table()` с явными колонками, без `Schema`, Eloquent-гидрации и generic `DbController`.
   - Использовать effective user из middleware, чтобы режим просмотра от лица сотрудника продолжал работать.

2. **Переключить экран Employee Today**
   - Удалить отдельные запросы `/api/db/competencies` и `/api/db/career_goals`.
   - Получать задачи, уведомления, компетенции и цели из одного React Query-запроса.
   - Считать завершённые цели по `status`/`progress`, а не по отсутствующему `is_completed`.
   - Сохранить текущие loading/empty/error состояния без изменения внешнего вида.

3. **Сохранить общий счётчик уведомлений**
   - Оставить общий hook уведомлений совместимым с новым ответом или использовать тот же кэш Today, чтобы на экране сотрудника не возникал второй сетевой запрос.
   - Фоновый запрос уведомлений по-прежнему не должен открывать глобальный circuit breaker.

4. **Защитить generic путь**
   - Добавить статические колонки `competencies` и `career_goals` в карту горячих таблиц `DbController`, чтобы другие страницы не выполняли metadata lookup для этих таблиц.
   - Некорректные запрошенные колонки должны игнорироваться/возвращать понятную 4xx-ошибку, но не приводить к 500.

5. **Проверки**
   - Backend feature-тест: сотрудник видит только собственные задачи, уведомления, компетенции и цели; другой пользователь недоступен.
   - Проверка завершённости целей через `status/progress`.
   - Frontend-тест: Employee Today больше не вызывает `/api/db/competencies` и `/api/db/career_goals`.
   - PHP lint и профильные frontend-тесты.
   - После выкладки — E2E под боевой учёткой: в Network должен остаться лёгкий Today endpoint с `200`, а четыре прежних запроса экрана не должны выполняться.

## Технический результат

```text
Employee Today
      |
      v
GET /api/employee/today
      |
      +-- tracker_tasks       (явные поля, limit 100)
      +-- notifications       (явные поля, limit 20)
      +-- competencies        (skill_value, limit 200)
      +-- career_goals        (id, title, status, progress, limit 100)
```

Это устраняет не очередной отдельный симптом, а все четыре generic DB-чтения стартового экрана сотрудника.
