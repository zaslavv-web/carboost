# План: 15 правок по демо-контенту и функционалу

## Что подтверждено при разборе

- Команда `demo:seed-extras` умеет создавать воркфлоу трекера и иерархию OKR, но падает на определении компании: автоопределение ищет профиль по `employee.76@demo.pikrosta.ru`, а затем по e-mail вида `%@demo.%`. Для компании demo_doom это не срабатывает — команда завершается с «Компания не найдена», поэтому воркфлоу и OKR так и не появились.
- Таблица `portal_post_comments` в БД есть и заполняется сидером, но страница сообщества (`CommunityDetail.tsx`) её вообще не читает — комментариев в UI нет.
- В чате сообщение (`MessageBubble.tsx`) рисует только текст и время: ни имени отправителя, ни аватара, ни перехода в профиль.
- В корзине checkout блокируется при нехватке валюты, но добавление товара в корзину ничем не ограничено и не предупреждает.

## Порядок работ

### Волна 1. Контент и сидинг (пп. 1, 9, 11, 12, 13а, 14)
- Починить определение компании в `demo:seed-extras`: если явная опция не задана — брать компанию текущего демо-стенда по числу профилей (крупнейшая непустая), с понятной подсказкой и списком доступных компаний при неоднозначности.
- Расширить сидинг:
  - тесты (закрытые вопросы) и наполненные сценарии оценки — раздел «Сценарии и тесты» перестаёт быть пустым;
  - приглашения сотрудников (несколько статусов: отправлено, принято, истекло);
  - Performance: активный цикл с участниками, целями и оценками;
  - «Мои документы»: персональные документы для демо-сотрудников;
  - отсутствия за последние 6 месяцев (отпуска, больничные, отгулы) — чтобы «доля отсутствий» считалась.
- Ужесточить `verify()`: сидер падает, если после прогона какой-то из этих блоков пуст.

### Волна 2. Сообщества и чаты (пп. 2, 3, 4, 5)
- Комментарии к записям сообщества: список, добавление, удаление своего, счётчик.
- Карточка участника сообщества: клик по аватару → профиль, кнопка «написать в личку» → создание/открытие диалога.
- Упоминания `@`: выпадающий поиск по ФИО и e-mail внутри компании, вставка ссылки на профиль; в отрендеренном тексте упоминание кликабельно.
- В чатах у сообщения — аватар и имя отправителя: клик по имени открывает личку, клик по аватару — профиль пользователя.

### Волна 3. Компетенции и математика (пп. 5-компетенции, 6)
- Единая функция расчёта соответствия эталону (один модуль, используется и дашбордом, и попапом сравнения) — устраняет расхождение среднего балла.
- Раздельная трактовка данных: «нет эталона», «нет оценки сотрудника», «есть обе» — цвет и проценты только для полных пар; неполные показываются серым со статусом, а не зелёным.
- Сидинг компетенций дозаполняет пары «эталон + оценка» по всем ключевым навыкам, чтобы не оставалось однобоких строк.

### Волна 4. Навигация и drill-down (пп. 7, 8)
- Попап объяснения рисков: кнопка «Открыть раздел» ведёт в соответствующий раздел (People Analytics / список сотрудников с нужным фильтром), а не сбрасывает фильтры на месте.
- Опросы: страница детали опроса — сводная таблица «вопрос × распределение ответов»; для неанонимных опросов вкладка с поимённым разрезом «кто как ответил».

### Волна 5. Прочее (пп. 10, 13б, 15)
- Планы адаптации: вложения к шагам (загрузка файлов) и генерация шаблонных документов по типовым чек-листам.
- Документы: просмотр и скачивание документов других сотрудников для ролей с соответствующим правом (HR/HRD/руководитель), с проверкой на бэкенде.
- Магазин: при нехватке валюты кнопка «в корзину» отключается с подсказкой «не хватает N», в корзине позиция подсвечивается.

## Технические детали

- Бэкенд: расширение `SeedDemoExtras.php` (или отдельные приватные методы + новая команда для тяжёлого контента), новые эндпоинты для комментариев сообществ, поиска пользователей для `@`, деталей опроса и доступа к чужим документам; политики доступа — через существующие `BasePolicy`/`CompanyScopedPolicy`.
- Фронтенд: `CommunityDetail.tsx`, `Communities.tsx`, `MessageBubble.tsx`/`ConversationView.tsx`, `PulseSurveys.tsx` + новая страница детали опроса, `RiskAnalytics.tsx`, `AdaptationPlans.tsx`, `HrDocumentsPersonal.tsx`, `Shop.tsx`/`Cart.tsx`, общий модуль расчёта компетенций.
- Проверка: прогон Playwright под HRD и сотрудником демо-компании по каждому пункту, проверка логов сервера на 4xx/5xx, `php artisan test` и сборка фронта — работа не считается завершённой, пока остаются ошибки.

## Уточнения по умолчанию (скажите, если иначе)

- Добавление в корзину при нехватке валюты — блокируем, а не просто предупреждаем.
- Доступ к чужим документам — только роли HR/HRD/company_admin и непосредственный руководитель.
