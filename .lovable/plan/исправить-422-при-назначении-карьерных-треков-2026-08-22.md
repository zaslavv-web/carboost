# Исправить 422 при назначении карьерных треков

## Подтверждённая причина

`POST /api/superadmin/demo/career-tracks` намеренно отвечает `422`, если после выполнения команды в выбранной компании осталось `0` записей в `employee_career_assignments`. При этом ответ не содержит поля `message` или `errors`, поэтому интерфейс показывает только техническое `422`, а не вывод команды с реальной причиной.

Назначение создаётся только сотрудникам, у которых `profiles.position_id` совпадает с `from_position_id` активного шаблона. Сотрудники без должности и должности без исходящего шаблона сейчас просто пропускаются. Фолбэк также не создаёт трек для единственной должности в отделе. Дополнительно `control_employee_assignments` сейчас ошибочно возвращает общее число назначений компании, а не число для `employee.76`.

## Что изменить

1. **Сделать генерацию треков полной для выбранной компании**
   - строить недостающие активные шаблоны от фактических должностей компании;
   - для отдела с одной должностью подбирать корректную целевую должность из другого отдела, не создавая петлю `должность → та же должность`;
   - после генерации повторно назначать каждому сотруднику все шаблоны, начинающиеся с его текущей должности;
   - не менять должности сотрудников автоматически и не создавать дубли назначений.

2. **Возвращать точную диагностику вместо безымянного 422**
   - учитывать код завершения `demo:seed --only-career`;
   - отдельно считать сотрудников без должности, без подходящего шаблона, число созданных шаблонов и назначений;
   - при невозможности назначения возвращать понятное `message` и диагностические числа;
   - успешный идемпотентный повторный запуск считать успешным, если назначения в компании уже существуют.

3. **Исправить контроль конкретного сотрудника**
   - вычислять `control_employee_assignments` именно для `employee.76` домена выбранной демо-компании;
   - убрать из сообщения интерфейса вводящую в заблуждение цифру, если такого пользователя в выбранной компании нет.

4. **Показать результат в интерфейсе**
   - выводить серверное объяснение ошибки и диагностический вывод команды;
   - после успешного запуска обновлять статус выбранной компании и показывать фактическое число шаблонов и назначений.

5. **Проверить регрессии**
   - тест: компания с несколькими должностями получает шаблоны и назначения;
   - тест: отдел с одной должностью не остаётся без исходящего трека при наличии других должностей;
   - тест: повторный запуск не создаёт дубли;
   - тест ответа endpoint для успешного запуска и для сотрудников без назначенной должности.

## Технические детали

- `SeedDemoCompany.php`: расширить покрытие фактических должностей и вернуть структурированную статистику выполнения.
- `DemoSeedController.php`: проверять exit code команды, формировать `message`/`diagnostics`, корректно считать контрольного сотрудника.
- `SeedDemoCompany.tsx`: показывать содержательное сообщение и обновлять запросы статуса.
- Добавить unit/feature-тесты без изменения данных других компаний.
