# Этап 2: боевая проверка после сидинга

Сидинг контента прошёл. Дальше — сквозной прогон продакшена по ролям и точечные фиксы найденного.

## 1. Проверка результатов сидинга (прод, Playwright)
Учётка HRD (`hrd.01@demo.pikrosta.ru`). Проверяем, что контент реально виден в UI, а не только в базе:
- Магазин: товары, изображения, заказы, аналитика по товарам.
- Трекер: спринты и бэклог непустые, статусы валидные.
- Лента новостей: развёрнутые тексты, счётчики комментариев и реакций.
- База знаний, документы, КЭДО, сообщества, отсутствия.
- Опросы и планы адаптации: возможность провалиться в карточку.

Для каждого раздела: скриншот + список сетевых ошибок (не-200 ответов).

## 2. Известные незакрытые дефекты
- Модалка выбора «Today / Classic» появляется на каждой странице — должна показываться один раз и запоминать выбор.
- Drill-down по рискам и карьерным трекам через URL-фильтры.
- SCORM: проверить запуск курса без ошибки «Ссылка устарела» / 410.

## 3. Прогон по остальным ролям
После HRD — Employee, Manager, Company Admin, Superadmin: главный экран, «Сегодня», обучение, задачи, профиль. Проверяем и десктоп, и мобильный вьюпорт.

## 4. Права доступа
Точечная проверка ролевой модели: сотрудник не видит системные настройки и чужие данные; правила «просмотр/правка/скачивание» по пользователю, должности, отделу, роли отрабатывают на сервере (не только в UI).

## 5. Фиксы и деплой
Найденные ошибки чиню по ходу, затем: тесты (`vitest` + PHPUnit) → GitHub Actions **Deploy Backend** → повторный прогон проблемных экранов на проде.

## Технические детали
- Проверка через Playwright на публичном URL, вход реальной учёткой; логирование всех ответов с кодом != 200.
- Фронтенд-фиксы — в `src/`, бэкенд — в `backend-laravel/`, деплой существующими воркфлоу.
- Отчёт по каждому разделу: статус, найденные ошибки, что исправлено.
