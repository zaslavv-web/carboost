# План: восстановить и довести HRD/Employee сценарии до рабочего состояния

## Принцип выполнения

Задача не считается завершённой, пока каждый пункт ниже не пройден в браузере под реальной HRD/Employee-сессией и не зафиксирован результат:

- страница открылась;
- данные видны;
- действие сохраняется;
- после перезагрузки состояние не теряется;
- в консоли, runtime-логах и сетевых запросах нет релевантных ошибок;
- если пункт требует backend-деплоя, он не помечается готовым до проверки на актуальном стенде.

Текущий план по HRD/Employee был потерян/перезаписан планом по инвест-презентации. Поэтому сначала восстанавливается полный чек-лист из исходного документа, затем выполняется аудит фактического состояния, затем исправления.

- [ ] HR-менеджеру поступает уведомление о новой покупке.
- [ ] Для нематериального workflow-товара пользователь видит окно активации.

- [ ] Для материального товара пользователь указывает реквизиты получения: место и время.

## Технические детали

- Работать не «волнами», а по разделам из этого чек-листа.
- Перед каждым блоком перечитывать этот план, чтобы не потерять пункты.
- Не заменять фактическую проверку утверждением «маршрут грузится»: нужно проверить действие и сохранение после reload.
- Если backend-изменение требует деплоя, отдельно проверить актуальную версию backend/frontend перед финальной приёмкой.
- Если в текущем окружении нельзя проверить реальную доставку письма, фиксировать честный результат: приглашение создано, backend вернул статус, UI показывает статус доставки/ошибки.
