# 500 на GET /api/chats — диагностика и устранение

Ошибка на бою повторяется после предыдущей правки чатов. Точная причина пока не подтверждена: в текущем ответе нет тела ошибки, а последний известный лог был по другим эндпоинтам. Поэтому первый шаг плана — получить точную строку исключения, а не угадывать.

## Шаг 1. Достать точную ошибку (5 минут, без изменений кода)

На сервере, в каталоге бэкенда:

```
grep -n "api/chats" -n storage/logs/laravel.log | tail -30
grep -n "SQLSTATE\|Fatal error\|Allowed memory" storage/logs/laravel.log | tail -30
```

Нужны 10-15 строк вокруг последней записи со стек-трейсом. По ним станет ясно, какая из веток ниже верна.

## Шаг 2. Проверка гипотез по схеме

Эндпоинт обращается к колонкам, которых может не быть в боевой БД. Проверяем фактическую схему:

```
SHOW COLUMNS FROM chat_messages;   -- ждём deleted_at
SHOW COLUMNS FROM chat_participants; -- ждём last_read_at
SHOW COLUMNS FROM profiles;        -- ждём is_support, position_id
SHOW COLUMNS FROM chat_conversations; -- ждём company_id, last_message_at
```

Любая отсутствующая колонка из этого списка даёт ровно 500 на `/api/chats` — код выбирает их явно.

## Шаг 3. Исправление по результату

В зависимости от того, что покажут шаги 1-2, применяется один из вариантов:

- Отсутствует колонка → миграция, добавляющая её (`deleted_at`, `last_read_at`, `is_support`), плюс защита в контроллере: выборка колонок только из фактически существующих.
- Ошибка не по схеме (память, соединения, сериализация дат) → правка соответствующего места контроллера.
- Пользователь без `company_id` → диалоги отсекаются скоупом; поправить ветку фильтра, чтобы отсутствие компании не роняло запрос.

## Шаг 4. Защита от повторов

Чтобы следующий такой случай не требовал доступа к логам:

- Обернуть `ChatController::index` так, чтобы при исключении возвращался JSON с коротким `error_id`, а полный стек уходил в лог с тем же идентификатором.
- Фронт (`src/components/chat`) при ошибке чатов показывает пустой список и ненавязчивое уведомление вместо падения панели — сессия и остальная страница не страдают.

## Технические детали

Затрагиваемые файлы: `backend-laravel/app/Http/Controllers/Api/ChatController.php`, при необходимости новая миграция в `backend-laravel/database/migrations/`, `src/contexts/ChatContext.tsx` для мягкой деградации.
