# Довести до конца: проверка версии фронта после деплоя

## Текущее состояние (проверено сейчас)

- `https://growth-peak.pro/version.json` отдаёт `200 text/html` с содержимым `index.html` — то есть SPA-фолбэк всё ещё перехватывает файл.
- `https://growth-peak.pro/api/health` — `status: ok`, версия бэкенда `cfb6751`, БД в порядке.
- Правки воркфлоу (управляемый `.htaccess` с pass-through для существующих файлов, SSH-проверка `version.json`, устойчивый HTTP-чек) уже в репозитории, но на сервере ещё не применялись — деплой фронта после них не запускался. Поэтому причина фолбэка пока не подтверждена: это может быть либо старый `.htaccess`, либо отсутствие файла в веб-руте, либо перекрытие папкой `frontend/`.

## Правило работы (постоянное)

О готовности сообщаю только после фактической проверки боевого стенда, а не после правки кода:

1. Отдаю правки → пользователь запускает деплой (или деплой идёт автоматически).
2. Дожидаюсь окончания и сам проверяю прод: `version.json`, `api/health`, ключевые страницы через Playwright, консоль и сеть.
3. Если проверка красная — продолжаю копать в том же заходе, а не отдаю «готово».
4) В сообщении привожу, что именно проверил и с каким результатом.

## Шаги закрытия бага

1. **Запустить Deploy Frontend** — новые шаги воркфлоу сами скажут, где проблема:
   - шаг `Verify version.json on server (SSH)` покажет `ls`/`cat` для `WEB_ROOT/version.json` и для `WEB_ROOT/frontend/version.json`;
   - шаг применения `.htaccess` подменит файл целиком (бэкап `.htaccess.bak`) и напечатает первые 30 строк.
2. **Разобрать вывод** и добить причину по факту:
   - файл есть, HTTP всё равно HTML → правило перезаписи или кэш Nginx-прокси; правлю `public/.htaccess` / порядок правил, при кэше прокси добавляю проверку с обходом кэша и явный сброс.
   - файла нет в руте → чиню цель `rsync` / `WEB_ROOT` в конфиге деплоя.
   - файл лежит в `frontend/` и она перекрывает корень → выравниваю веб-рут и убираю дублирующую папку.
3. **Повторить деплой** и подтвердить: `version.json` отдаёт `content_type: application/json` и текущий SHA, `Cache-Control: no-store` на `index.html`.
4. **Сквозная проверка прода** через Playwright под HRD и Employee: ключевые разделы открываются, в консоли нет ошибок, в сети нет 4xx/5xx.
5. Только после зелёных пунктов 3–4 — сообщение о готовности с перечнем проверок.

## Технические детали

- Файлы: `.github/workflows/deploy-frontend.yml` (шаги `Cache headers`, `Verify version.json on server (SSH)`, `Apply .htaccess`, `Post-deploy check`), `public/.htaccess`.
- Признак успеха: `curl -sI https://growth-peak.pro/version.json` → `content-type: application/json`, тело содержит короткий SHA коммита.
- Диагностика фолбэка: сравнение поведения `manifest.json` (отдаётся корректно) и `version.json` укажет, дело в файле или в правиле.
