# «Nothing to migrate» — проверить, доехал ли бэкенд до сервера

Файл миграции `0044_00_00_000000_add_career_track_insight_indexes.php` в репозитории есть (последний в `backend-laravel/database/migrations`). Значит «Nothing to migrate» означает одно из двух: либо на сервере лежит старый код без этого файла, либо миграция уже применена ранее. Что именно — пока не проверено, это первый шаг.

## Шаг 1. Диагностика на сервере (без изменений)

В каталоге бэкенда на проде (`/home/gro7659365/growth-peak.pro/docs/backend`):

- `ls database/migrations | tail -5` — есть ли файл `0044_...`.
- `php artisan migrate:status | tail -10` — статус Ran/Pending для 0043 и 0044.
- `git log -1 --oneline` — какой коммит развёрнут.

Развилка:
- файла нет → код не доехал: деплой бэкенда;
- файл есть и Ran → индексы уже применены, миграции ни при чём, проблема в другом (см. шаг 3).

## Шаг 2. Если код старый — доставка

- Проверить, что workflow `.github/workflows/deploy-backend.yml` отработал на последнем коммите (Actions → статус, лог шага rsync/ssh).
- Если workflow не запускался или падал — разобрать причину по логу и починить (секреты, путь на сервере, права).
- После выката: `php artisan migrate --force`, затем `php artisan optimize:clear`.

## Шаг 3. Проверить, что новое реально работает

Независимо от миграции индексы — только про скорость. Функциональность зависит от новых маршрутов:

- `curl -H "Authorization: Bearer <token>" https://<домен>/api/hrd/employee-map` — должен отдать 200 и заголовок `X-Db-Read-Path: hrd-map-v1`. Если 404 — на сервере старый код, шаг 2.
- `GET /api/career-tracks/employee/{userId}` и `GET /api/analytics/career-tracks` — те же 200.
- Замер времени карты сотрудников до/после.

## Техническая часть

- Миграция идемпотентна: индексы оборачиваются в try/catch, повторный запуск безопасен.
- Если на проде MySQL уже имеет часть индексов под другими именами, `migrate` пометит миграцию как выполненную без ошибок — это ожидаемо.
- Отдельно проверить фронт: собранный бандл должен содержать маршрут `/career-tracks/employee/:userId`, иначе нужен деплой фронта (`deploy-frontend.yml`).
