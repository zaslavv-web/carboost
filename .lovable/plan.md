## Найденная проблема

Перевод монет на бою не работает: `POST /api/currency/transfer` возвращает 422 «The recipient id field must be a valid UUID».
Причина подтверждена запросами: `GET /api/currency/recipients` отдаёт `user_id` в виде числовых строк (например `1262`), а валидация в `CurrencyController::transfer` требует `uuid`. То есть любой перевод из UI будет отклонён.

Второе (не баг, а данные): `earn-rules` возвращает пустой список — у компании нет активных правил в `gamification_reward_types`, поэтому страница «Как заработать» показывает заглушку.

## Что сделаем

1. В `CurrencyController::transfer` заменить правило `recipient_id => required|uuid` на `required|string|max:64` (идентификаторы пользователей в этой БД — числовые). Проверка «получатель существует и в моей компании» уже есть и остаётся главной защитой.
2. Прогнать перевод повторно на бою (малая сумма) и убедиться, что создаются две записи в `currency_transactions` и корректно пересчитываются балансы.
3. Опционально: если нужно, чтобы страница «Как заработать» не была пустой — завести базовый набор правил начисления для компании (отдельным шагом, по вашему решению).

## Технические детали

- Правка в одном файле: `backend-laravel/app/Http/Controllers/Api/CurrencyController.php`, метод `transfer`.
- Деплой: `git pull origin main` на боевом + сброс кэшей (`config:clear`, `route:clear`). Миграция для этого шага не нужна — она уже применена (в `balance` приходят `transfers_enabled` и `transfer_limit_per_day`).
