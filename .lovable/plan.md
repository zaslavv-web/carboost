# Резолюция по внешнему аудиту

Проверил каждое замечание по репозиторию. Ниже — вердикт и что реально стоит чинить.

## P1 — критические

| Замечание | Вердикт | Факт |
|---|---|---|
| Нет `routes/web.php` | **Справедливо** | Файла в репозитории нет, при этом `bootstrap/app.php:155` его подключает. Прод жив только потому, что маршруты закешированы/файл создан вручную на сервере — на чистом клоне приложение упадёт. |
| Нет `routes/console.php` | **Неверно** | Файл есть, в нём расписание `mail:heartbeat` и `risks:compute`. |
| Прямые INSERT/SELECT в `auth.users` Supabase | **Неверно (перепроверено построчно)** | `AuthUserService.php` — три вставки, все `DB::table('users')->insert(...)` (строки 56, 123, 190), схемы `auth` нет. `AuthController.php:30` и `UsersController.php:45` проверяют уникальность email через `DB::table('users')`, в коде даже стоит комментарий «не auth.users!». Таблица `users` — не VIEW на `auth.users`, а обычная таблица, созданная миграцией `0002_00_00_000000_create_users_table` (`Schema::create('users')`). Единственные упоминания `auth.users` в исполняемом коде — в тестовых хелперах `tests/WithDomainUsers.php:34` и `tests/Feature/AuthControllerTest.php:31`; они на прод не влияют, но их стоит переписать на `users`. |
| Пустой `APP_KEY` | **Неверно** | Ключ задан и в корневом `.env`, и в `backend-laravel/.env`. Аудит, похоже, смотрел `.env.example`. |
| Не настроены Google/Mail/AI | **Частично** | Google OAuth и Unisender Go заполнены боевыми значениями. `AI_API_KEY=YOUR_AI_API_KEY` — плейсхолдер, но ключи AI хранятся пер-компанийно в БД (`ai_settings.api_key_enc`, шифрование `Crypt`), env — только фолбэк. |

## P2 — UX

| Замечание | Вердикт |
|---|---|
| Незавершённый Google-флоу при ошибке | Требует проверки на живом флоу; в текущем коде редирект есть, но негативные ветки не покрыты тестом. Проверяемо. |
| Нет индикаторов загрузки | Спорно: у AI-экранов состояния есть, но не везде единообразно. |
| `proxy_read_timeout 300s` | Не проблема: AI-запросы идут короткими чанками (8 КБ), таймаут запаса хватает. |
| Слабая клиентская валидация | Частично справедливо: часть форм полагается на серверные 422. |
| Нет fallback на HTML-ответ | **Неверно**: shutdown-handler в `bootstrap/app.php` отдаёт JSON с `error_id` даже при фатале, фронт это распознаёт. |

## P3 — масштабирование

| Замечание | Вердикт |
|---|---|
| Архитектурная зависимость от Supabase | **Неверно**: Phase 13 её убрала, рантайм на Laravel. |
| `CompanyScope` без индексов | **Неверно как «нет гарантий»**: составные индексы `['company_id', ...]` расставлены в миграциях (chat, analytics, performance, pulse и др.). Локально возможны пробелы на отдельных таблицах. |
| Нет кэширования | Частично: `Cache::` используется точечно (GeoIP, профили, e-mail-конфиг), сплошного слоя нет. |
| Монолитный `DbController` (911 строк, 33+ таблицы) | **Справедливо**, но осознанно: это generic-CRUD с горячими вайтлистами колонок; тяжёлые сущности уже вынесены в `ProfileController`, `EmployeeReadController`. |
| Нет версионирования API | **Справедливо**: префикса `v1` нет. Реальный риск низкий — клиент один и деплоится вместе с бэком. |
| Нет rate limiting на AI | **Справедливо**: `throttle` стоит только на публичных эндпоинтах (10/мин, 30/мин), группа `ai/*` без лимита. Это единственное P3 с прямым денежным риском. |
| Смешение ответственности в `AuthUserService` (414 строк) | Частично справедливо, рефакторинг не срочный. |

## Итог

Из 16 пунктов подтверждаются полностью 4: отсутствующий `routes/web.php`, отсутствие rate limiting на AI, отсутствие версионирования API, монолитный `DbController`. Три «критических» пункта (Supabase, `APP_KEY`, `console.php`) фактически неверны — аудит смотрел на `.env.example` и устаревшую архитектуру до Phase 13.

## Что предлагаю сделать (по убыванию пользы)

1. Добавить `backend-laravel/routes/web.php` (минимальный, только health/redirect) — устраняет единственный реальный P1.
2. Навесить `throttle:20,1` на группу `ai/*` и отдельный дневной лимит на парсинг документов.
3. Пройтись по миграциям и добить индексы `company_id` там, где их нет (список составлю по факту).
4. Опционально: алиас `/api/v1/*` на текущие маршруты, чтобы зафиксировать контракт без ломки клиента.

Пункты 2–4 — отдельные небольшие правки; скажите, какие делать.
