# Карьерные треки: детализация по сотруднику, аналитика, ускорение карты

## 1. Провалиться в карьерный трек сотрудника

Новая страница `/career-tracks/employee/:userId` (доступ: hr, hrd, company_admin, manager по своим, superadmin).

Содержимое:
- Шапка: сотрудник, должность, отдел, текущая цель трека (из → в), статус (активен/завершён/провален), прогресс «шаг N из M» с полосой.
- Таймлайн этапов: каждый шаг трека — статус (пройден / текущий / впереди / отклонён), дата прохождения, комментарий сотрудника, вложенные файлы, кто и когда проверил, причина отклонения, номер попытки.
- Таблица тестирований по треку: дата, название теста, шаг, результат (баллы / максимум, %), «зачёт/незачёт» относительно минимального порога шага, число попыток.
- Клик по строке теста разворачивает разбор: вопросы, ответ сотрудника, правильный ответ, разбивка по компетенциям.
- Если у сотрудника несколько треков — переключатель треков сверху.

Точки входа:
- Вкладка «Назначения» на `/career-tracks` — строка сотрудника кликабельна.
- Карточка сотрудника в карте сотрудников — кнопка «Карьерный трек».

## 2. Аналитика по карьерным трекам

Расширение вкладки аналитики треков (сейчас там только участники и распределение по шагам):
- Прогресс переходов: воронка «назначено → на шаге 1..N → завершено» по каждому треку, доля дошедших до каждого этапа.
- Наиболее трудные места: рейтинг шагов по доле отклонений, среднему числу попыток, средней длительности застревания и доле проваленных тестов.
- Отделы с труднопроходимыми треками: таблица отделов — средний прогресс, доля завершивших, среднее время на шаг, индекс сложности.
- Скорость сотрудников: списки «быстрее всех» и «отстают» — сравнение фактического темпа (шагов в месяц) с медианой по треку, бейдж отставания, ссылка на карточку трека сотрудника (пункт 1).
- Фильтры: трек, отдел, период; клик по элементу ведёт в детальную карточку сотрудника.

## 3. Почему карта сотрудников грузится долго

Подтверждено по коду `src/components/HRDEmployeeMap.tsx`: карта делает 4 «широких» запроса через универсальный слой `laravelDb`, среди них `hr_tasks` с `select("*")` (тянет описания всех задач компании) плюс отдельный запрос всех `hr_task_assignees`, а также все профили и все балансы компании. Это тот же тяжёлый generic-путь, который раньше упирался в лимиты памяти.

Что делаем:
- Один агрегирующий эндпоинт `GET /hrd/employee-map` (по образцу `EmployeeReadController`): raw-SQL, только нужные поля, задачи без `description`, счётчики исполнителей вместо полных списков, балансы join-ом. Один запрос вместо четырёх.
- Ленивая загрузка «тяжёлого»: полные данные задачи и данные боковой панели (композит, магазин) грузятся только при выборе сотрудника — как сейчас, но с отдельными лёгкими эндпоинтами.
- Кэширование в React Query (`staleTime` 60 c) и скелетон вместо блокирующего спиннера, чтобы граф появлялся сразу после профилей.
- Индексы БД под выборки: `hr_tasks(company_id, created_at)`, `hr_task_assignees(task_id)`, `employee_career_assignments(user_id)`, `career_step_submissions(assignment_id, step_order)`.

## Техническая часть

Backend (`backend-laravel`):
- `CareerTrackDetailController`: `GET /career-tracks/employee/{userId}` (назначения, шаги шаблона, сабмишены с файлами, попытки тестов), `GET /career-tracks/attempt/{id}` (разбор ответов).
- `CareerTrackAnalyticsController`: `GET /analytics/career-tracks` — воронка, сложность шагов, срез по отделам, темп сотрудников (raw SQL, агрегаты на стороне БД).
- `HrdMapController`: `GET /hrd/employee-map` — агрегированные данные карты.
- Миграция с индексами; политика доступа через существующий `BasePolicy` (hr/hrd/company_admin/superadmin, manager — только своя команда).

Frontend:
- Новая страница `src/pages/EmployeeCareerTrack.tsx` + маршрут в `src/App.tsx`.
- Компоненты `CareerTrackTimeline.tsx`, `CareerTrackTestsTable.tsx`, `CareerTrackTestReview.tsx`.
- Расширение `src/components/HRDCareerTracksAnalytics.tsx` (воронка, сложность шагов, отделы, темп).
- `HRDEmployeeMap.tsx` переводится на новый агрегирующий эндпоинт, добавляется кнопка перехода в трек.
- Строки i18n (ru/en), Vitest на расчёт темпа и сложности шагов, PHPUnit на агрегаты аналитики.
