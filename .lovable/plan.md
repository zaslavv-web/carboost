# Исправление демо-контента, drill-down фильтров и сравнения с эталоном

## 1. Демо-контент, которого нет (пункты 1, 2, 4)

- Новость: сидер обязан создать одну эталонную публикацию в ленте (заголовок, форматированный текст, изображение, видео, файл) и падать с ошибкой, если после прогона в ленте компании нет ни одной новости с медиа.
- Воркфлоу и OKR: сидер обязан создать цели/OKR и рабочий процесс для сотрудников выбранной компании (включая employee.76) и проверять результат счётчиком после вставки — «тихое» завершение без данных запрещено.
- Доля отсутствий: заполнить `leave_requests` одобренными отпусками/больничными за последние 6 месяцев, чтобы график «Доля отсутствий» перестал быть пустым. Дополнительно на графике показывать явную подпись «нет данных», если ряд пустой.

Все три проверки оформляются как самопроверка внутри команды сидинга: после прогона печатается сводка (новости / OKR / воркфлоу / отсутствия) и ненулевые ожидания.

## 2. Drill-down из People Analytics и дашбордов (пункты 3, 6, 7)

- Клик по сегменту «Стажевые когорты» открывает список сотрудников, отфильтрованный по этой когорте, с активной подсветкой выбранной когорты в панели фильтров (а не общий список). Отдельно: когорта «< 3 мес» и сотрудники на испытательном сроке помечаются признаком «стажировка».
- Клик по столбцу «Топ-15 позиций» и по департаментам открывает список с уже применённым фильтром должности/департамента (сейчас фильтр не срабатывает из-за расхождения значений в графике и в справочнике — сопоставление будет по нормализованному названию).
- Переход из любого дашборда сбрасывает ранее применённые фильтры: новый drill-down формирует чистый набор параметров URL, а не накладывается на предыдущий. Поэтому «роли → компетенции → должность» больше не даст пустую таблицу.
- В шапке списка сотрудников остаются видимые чипы активных фильтров с кнопкой «сбросить всё».

## 3. Таблица сотрудников (пункт 5)

Убрать дублирование должности: должность отображается в одном месте. В строке с ФИО остаются имя и email, а должность выносится в отдельный столбец «Должность» (рядом с департаментом). В мобильных карточках — одна строка с должностью.

## 4. Сравнение с эталоном должности (пункт 8)

- Заполнить эталонные профили компетенций у должностей демо-компании (целевые значения по шкале 0–100), без них сравнение бессмысленно.
- Исправить расчёт соответствия: если у должности нет эталона — показывать «эталон не задан» и ссылку на настройку профиля вместо числа; если эталон есть — процент считается по единой шкале и ограничивается диапазоном 0–100 %. Никаких значений в тысячах.

## Проверка перед завершением

- Прогон сидинга на демо-компании с выводом сводки по созданным сущностям.
- Playwright-сценарий под HRD: People Analytics → клик по когорте, по должности, по департаменту, затем «роли → компетенции → должность»; список сотрудников; карточка сотрудника со сравнением с эталоном; лента с новостью; OKR и воркфлоу.
- Проверка отсутствия ошибок в консоли и 4xx/5xx в сетевых запросах на каждом шаге; задача не считается готовой, пока в логах есть ошибки.

## Технические детали

- Drill-down получает единый помощник построения URL, который создаёт новый `URLSearchParams` (без наследования текущих), чтобы предыдущие фильтры не «залипали».
- Фильтры должности/департамента сопоставляются по нормализованной строке (trim + регистр), совпадая с агрегацией на бэке.
- Данные по отсутствиям берутся из `leave_requests` (`status=approved`), эндпоинт уже готов — недостаёт только данных.
- Расчёт соответствия эталону выносится в одну функцию с защитой от деления на ноль и клампом 0–100.
