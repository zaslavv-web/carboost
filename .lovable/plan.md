# Учётки компании demo_doom (по одной на роль)

Данные пользователей лежат в боевой MySQL Laravel, а не в базе этого проекта, поэтому получить их можно только с продакшн-сервера. В репозитории нет ни компании, ни сидера с именем `demo_doom` — значит компания заведена вручную в проде.

## Что делаю

1. Добавляю artisan-команду `demo:creds` в `backend-laravel/app/Console/Commands/`:
   - аргумент: часть названия компании (`demo_doom`), поиск по `companies.name` через LIKE;
   - берёт по одному пользователю на каждую роль (`employee`, `manager`, `hr`, `hrd`, `company_admin`) из `users` + `profiles` + `user_roles` со скоупом `company_id`;
   - опция `--set-password=` — задаёт этим выбранным учёткам единый известный пароль (bcrypt), чтобы ими можно было войти; без опции команда только показывает список без паролей (хеши необратимы);
   - выводит таблицу `роль | email | ФИО | пароль`.
2. Вы делаете на сервере `git pull` + `php artisan config:clear`, затем запускаете:
   `php artisan demo:creds "demo_doom" --set-password='DemoPass!2026'`
3. Я разбираю вывод и отдаю итоговую таблицу учёток по ролям.

## Технические детали

- Команда работает только через `DB::table` (без Eloquent-гидрации) — согласуется с текущим подходом на проде.
- Если по какой-то роли в компании нет пользователя, команда так и пишет «нет учётки» и предлагает создать её флагом `--create-missing` (создаёт `users` + `profiles` + `user_roles` с `company_id` компании и тем же паролем).
- Смена пароля затрагивает только найденные учётки указанной компании, не трогает боевых пользователей других компаний.

## Альтернатива без изменений кода

Если менять код нельзя — можно один раз выполнить SQL прямо на сервере (`SELECT ... FROM users JOIN profiles JOIN user_roles WHERE company_id = ...`) и прислать вывод: тогда я отдам список email по ролям, но пароли всё равно придётся сбросить, так как в базе только хеши.
