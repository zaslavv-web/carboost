# SCORM-уроки и единый редактор контента

## Цель
Устранить 404 при открытии SCORM-модулей, сделать клик по уроку явно открывающим материал и заменить Markdown-поля уроков и корпоративных новостей полноценным визуальным редактором с изображениями и видео.

## Что изменится

### 1. Надёжная выдача SCORM
- Проверить боевой курс и фактические файлы пакета через диагностический endpoint под HRD.
- Убрать зависимость URL ассета от устаревающего UUID каталога: лаунчер будет обращаться к ассетам через идентификатор курса, а сервер — находить актуальный пакет курса и проверять доступ пользователя.
- Сохранить относительные пути SCORM (HTML, JS, CSS, изображения, шрифты, аудио и видео), корректные MIME-типы и byte-range для перемотки видео.
- При отсутствии файла показывать в плеере понятную ошибку вместо пустого блока; для автора — диагностические сведения без раскрытия серверных путей.
- Проверить, что деплой не удаляет `storage/app/private/scorm-packages`; при необходимости исключить пользовательское хранилище из очистки/rsync.
- Предупреждение браузера про `allow-scripts + allow-same-origin` устранить архитектурно: SCORM будет работать в отдельном origin-safe контексте либо без лишнего внешнего sandbox. Совместимость с `window.parent.API` сохраняется.

### 2. Поведение списка модулей
- Сделать строки уроков доступными кнопками с явными состояниями: выбран, загружается, открыт, ошибка.
- При клике гарантированно менять активный урок, прокручивать к плееру на мобильном и перезапускать тикет для выбранного SCORM-урока.
- Добавить повторную загрузку и открытие материала в отдельном окне как резервный сценарий.

### 3. Единый визуальный редактор
- Добавить переиспользуемый rich-text editor на TipTap для уроков и корпоративных новостей.
- Панель: обычный текст и заголовки, семейство и размер шрифта, жирный, курсив, подчёркивание, списки, внутренние/внешние ссылки, отмена/повтор.
- Вставка изображений и видео: загрузка файла в хранилище компании, индикатор прогресса, подпись/alt для изображения, вставка безопасной внешней ссылки для поддерживаемых видеосервисов.
- Хранить HTML в существующих текстовых колонках для обратной совместимости; старый Markdown продолжит отображаться корректно.
- Безопасно очищать HTML на клиенте и сервере: запрещать scripts, event-handler атрибуты, небезопасные URL и произвольные iframe.

### 4. Медиа и доступ
- Добавить отдельное хранилище `content-media` и API загрузки с проверкой роли, компании, MIME и размера.
- Изображения и видео будут доступны через контролируемые URL, пригодные для `<img>`/`<video>`, без bearer-токена в HTML и без раскрытия файлов других компаний.
- Поддержать responsive-рендеринг изображений и HTML5-видео; для больших видео — потоковую отдачу с Range.

### 5. Проверка
- Backend-тесты: импорт ZIP, все уроки пакета, относительные ассеты, изображения/видео, Range, старый и новый URL, запрет чужой компании.
- Frontend-тесты: выбор каждого модуля, состояния загрузки/ошибки, сохранение и повторный показ форматированного текста и медиа в уроке и новости.
- После деплоя пройти боевой сценарий HRD: загрузить предоставленный SCORM ZIP, открыть каждый урок, затем создать обычный урок и новость с заголовком, ссылкой, изображением и видео.

## Технические детали
- Новые зависимости редактора: `@tiptap/react`, `@tiptap/starter-kit`, расширения link/image/underline/text-style/font-family.
- Существующие поля `lessons.content` и `portal_posts.body_md` остаются; формат определяется как HTML/legacy Markdown без миграции данных.
- Изменения затронут SCORM controller/routes, CourseView/CourseAuthoring, CorporateFeed, storage configuration/controller и новый общий editor/renderer.
